# TEYVA ontology (`teyva.owl`)

Generated by `platform/backend/infrastructure/ontology/build.py` from
`platform/backend/domain/communes.py` — regenerate after any T-Box or commune-list change:

```bash
cd platform/backend && export PYTHONPATH=.
python -m infrastructure.ontology.build
```

## Classes

`Territory` (⊐ `Commune`, `Corregimiento`) · `TerrainFeature` (⊐ `Slope`, `TWI`, `NDVI`,
`SoilType`, `Elevation`) · `HydroFeature` (⊐ `Stream`) · `Trigger` (⊐ `RainfallEvent`,
`SeismicEvent`) · `Exposure` (⊐ `Dwelling`, `CriticalFacility` ⊐ `Hospital`, `School`,
`Shelter`) · `LandslideEvent` · `HazardAssessment` · `DataQualityFlag`.

## Object properties

`locatedIn`, `adjacentTo` (symmetric), `drainedBy`, `hasTerrainFeature`, `exposes`,
`triggeredBy`, `hasHistoricalEvent`, `assessedBy`.

## Datatype properties

Mirror DB column names exactly, so A-Box population from Postgres (`specs/005-knowledge-graph/`)
is a straight mapping: `canonical_id`, `official_code`, `nombre`, `is_ladera`, `slope_p90_deg`,
`twi_p90`, `ndvi_min`, `hazard_fraction`, `precip_mm`, `magnitude`.

## Individuals

One per commune/corregimiento (`territory_<canonical_id>`), generated from
`domain/communes.py::COMMUNES` — never hand-typed. `domain/communes.py` is the single source of
truth for the territory; a second list anywhere (including here) is a bug.

## SWRL

The geotechnical rules in `domain/rules/catalog.py` are the executable specification (see
ADR-0002 for why: no JVM in crons, testable without I/O). This ontology mirrors that catalog as
`SymbolicRule` individuals (one per `Rule`, generated from `CATALOG`, never hand-typed) carrying
`rule_id`, `priority`, `provenance` and a `swrl_sketch` string.

`swrl_sketch` is a human-readable condition→effect sketch, **not an executable owlready2 `Imp`/
SWRL rule** — the ontology's per-feature class model (slope lives on `Slope`, not directly on
`Territory`) doesn't map cleanly onto flat SWRL rule bodies without a larger ontology redesign
than this spec's scope covered. It documents the formal correspondence; it does not run.

`tests/test_ontology.py::test_swrl_sketch_rule_ids_match_the_rule_catalog` is the drift guard:
it asserts the ontology's `SymbolicRule.rule_id` set equals `domain.rules.catalog.CATALOG`'s ids
exactly, so the two representations cannot silently diverge.

## Loading at runtime

Use `infrastructure/ontology/loader.py`, never load the file directly elsewhere —
`ontology_version()`, `individuals_for_commune()` and `rule_ids()` are the supported interface.
