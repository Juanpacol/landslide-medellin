# SPEC-NNN — Title

## spec.md

**Problem.** What is broken or missing today, in one paragraph, with a pointer to the code or
audit finding that shows it.

**Goal.** What this spec delivers, stated as an outcome, not a task list.

**Non-goals.** What is explicitly out of scope, to stop scope creep in `plan.md`.

**Acceptance criteria.** A short numbered list, each one testable.

---

## plan.md

**Architecture.** Where this lives in the layered architecture (`domain/application/
infrastructure/api`), and why.

**Files touched.** New files and modified files, with a one-line role for each.

**Interfaces.** Key function/class signatures this spec introduces, so downstream specs can
depend on them without reading the implementation.

**Sequencing.** What this spec depends on, what depends on it.

---

- [ ] Task 2 — ...  (verifies: ...)
